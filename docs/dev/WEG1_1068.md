## 1. The design in one paragraph

Both phase host pools are built from ONE absolute upstream knob,
`--hicache-size` (GB), the TP pin ROW-coupled to the PP pool
(`phase_flip_boot.py`, `#1068 TP PIN ROW MISMATCH` raises on divergence);
the mamba anchor pools of both phases from `--hicache-mamba-host-mib` (MiB
per rank, MIN-synced across the group, `synced_from_local=` on the
provenance line). The prefetch budget is the upstream property
`prefetch_capacity_limit = int(fraction x mem_pool_host.size)` read live
(no stored copy, no floor, no symmetrisation); the rate verdict is the
upstream counter form in both roles (`prefetch_tokens_occupied`). A
`rate_limited` verdict is never a decline: the request is marked deferred,
retried every pass in `kv_arrival_seq` order, held from prefill by PP0 only,
and every mark has exactly one named exit (`LANDED`, `DEFER EXPIRED`,
`DEFER RELEASED`, `DEFER DROPPED`, `DEFER CLEARED AT CUTOVER`). At the
cutover the WHOLE run-willing population (retracted residents AND queue
occupants) is re-issued through the one upstream intake site
(`_add_request_to_queue -> _prefetch_kvcache`) under the incoming binding
generation, in arrival order, occupants not stamped as retracts. Every
exit behind the #915 gate has a term and one line. The per-request seam
copy (A) and its restore path are deleted; the HiCache store is the single
carrier. The verdict stays PP0 (#968).

## 2. Bounded loss (the commit sentence of section 4.5, verbatim)

Deleting the per-request seam copy loses at most chunked_prefill_size
(4096, log 175) tokens of recompute per resident and cutover, and only for
residents whose prompt fits ONE chunk and that are re-allocated in the
layout the copy was taken in: for prompts > 4096 restore_seam_state refused
structurally (schedule_batch.py:3278-3279 PREFILL INCOMPLETE, 7 refusals x
3 ranks on boot_855_968umbauB_228a66db32: log 67083-67091, 151125-151143,
153597-153743, 154534-154536, 191117-191133, 191593-191609, 191645-191658),
for layout changes it refused at :3388-3449 (2 x 3 ranks: log
4688/4690/4735, 191591/191602/191607); the measured restore on that boot
was exactly one request (7fb95686, 67 rows, log 151763-151764/151812-151813/
151861-151862). The store path carries a superset of the copy (all 16
layers vs the rank-local stage slice, #706) plus the GDN leaf anchor at
kv_committed_len (mamba_component.py:1057-1119; #969L committed=14922 ==
copy extent 14922, log 154287 vs 191645) and is the single carrier after
this commit, conformant with the one-chunk law (#939).

## 4. Launcher (slice 5): `/spinning/gpu-arb/boot_855_train0901.sh`

Backup of the pre-slice file: `boot_855_train0901.sh.bak_20260902_174258_pre_weg1_slice5`.

The arithmetic lives in `/spinning/gpu-arb/devtools/weg1_host_sizing.py`
(importable; pinned by `test/registered/unit/managers/test_weg1_launcher_acceptance_1068.py`):

```
demand_rows = (n_resident + n_queue + 1) x prompt_max
    n_resident = max_running_requests            (config, 8)
    n_queue    = WEG1_QUEUE_DEPTH                 (knob, default = max_running_requests)
    prompt_max = WEG1_PROMPT_MAX_TOKENS           (knob, default 39365 = Boot-2 load class)
S_demand = ceil(demand_rows x cell_pp0 / 1e9)    (cell_pp0: previous log L8 `cell_pp=` max over ranks,
                                                  else WEG1_CELL_PP0_BYTES, else 16384)
S_ledger = floor((MemAvailable - 16 GB - 10 GiB - 27 GiB - 2 x ranks x M_MIB) / 8)   [8 = PP 2S + TP pin 6S]
S        = min(S_demand, S_ledger)               rows(S) = S*1e9 // cell_pp0 + 1 (pool_host/base.py:140-147)
M_MIB    = WEG1_MAMBA_HOST_MIB (default 2400, spec section 5 acceptance value; formula 69 x 37.41 = 2582 -> 2600 printed beside it)
```

On the Boot-2 configuration with MemAvailable 119 GB: demand 669205 rows
(S_demand 11) > ledger 366211 rows (S_ledger 6) -> the A11.2 line
`#1068 HOST POOL DEMAND EXCEEDS LEDGER demand_rows=669205 (n_resident=8
n_queue=8 chain_lag=1 prompt_max=39365) ledger_rows=366211
spans_at_prompt_max=9.30 -> pool sized to the ledger; ...` is printed and
the boot runs with `--hicache-host-role staging --hicache-size 6
--hicache-mamba-host-mib 2400`. Refusal (exit 2, no fallback): S_ledger < 1,
ledger rows < max_running_requests x chunked_prefill_size, anchor slots <
device_slots + max_running_requests + 1. Every term is printed with its
provenance on ONE `#1068 WEG1 SIZING TERMS` line (A11.1);
`WEG1_PROMPT_MAX_TOKENS` is exported so L8 prints `spans_at_prompt_max`
(A11.4).

`--dry-run` (or `DRY_RUN_ARG=1`) prints the terms, the ledger verdict, the
serving path the flags select (UnifiedRadixCache, `mem_cache/registry.py:191`,
+ HybridCacheController, `hybrid_pool_assembler.py -> hybrid_cache_controller.py:158`,
+ phase flip with HiCache rebind) and the exact argv, and starts nothing,
writes no log, arms nothing, queries no GPU.

Deadman: before arming, deadmen whose argv names port 30030 and another log
are killed by PID (stale sweep, never a broad pkill); then
`GRACE_S=600 boot_deadman.sh <log> 30030` is armed and the proof line
`deadman pgrep proof: N process(es) pid(s) ... whose argv carries THIS
boot's log <log>` is tee'd INTO the boot log, where acceptance A10 greps it.
