Instruments where the figures come from

All figures above come from inter-process communication, no boot log is read (NF operator 30.09.): per boot state.json, events.jsonl and per rank rankstate/<G>/*.rankstats (cumulative counters, written by the rank about every 1 s); rigdash takes a sample every second and computes rates from the deltas. Where a value has no IPC field, it says “missing in IPC” with the writer that would have to supply it.

Prefill tok/s (compute rate) = Δprefill.new_tokens / Δprefill.compute_ms per rank; the tile shows the slowest rank, because a PP stage or a TP partner limits every chunk. This is device time, hence compute-honest: idle time between requests does not lower it.

Wall-clock throughput = Δprefill.new_tokens of the first rank divided by the time of the samples with work (idle samples do not count); now = the last sample.

Decode tok/s = Δdecode.tokens (TP0) / Δts over the samples with work; per stream = that divided by decode.running; compute rate = Δdecode.tokens / Δdecode.gpu_ms.

The dashboard sends no request to any model except GET /weg2/state every 10 s. VictoriaMetrics (:8428) fetches /metrics of the front every 15 s (user order 01.10.: time-series DB).

TTFT = arrival at the front → first content from D (LEG2-FIRST-CONTENT), as IPC counter state.json front.arrival_seat.ttft_* (NF front); the sampler writes it to VictoriaMetrics (weg2_front_ttft_*), the tile reads it via PromQL. The 27B front does not have it until the image with weg2_ttft_seconds.
